## Response Section
### ความหมายของตัวอักษร
A: Atomicity ในหนึ่ง Transaction ทุกคำสั่งจะต้องทำงานสำเร็จทั้งหมด ข้อมูลจึงจะถูกบันทึก (Commits) และถ้ามีคำสั่งใดคำสั่งหนึ่งล้มเหลว ระบบจะทำการยกเลิก (Rollback) ข้อมูลกลับไปสู่สถานะเดิมก่อนเริ่ม Transaction ทั้งหมดทันที
C: Consistency ทุกครั้งที่จบ Transaction (ไม่ว่าจะสำเร็จหรือล้มเหลว) ข้อมูลที่เกี่ยวข้องกันจะต้องถูกแสดงผลออกมาอย่างถูกต้องและสอดคล้องกันเสมอ
I: Isolation เมื่อมีหลาย Transaction เกิดขึ้นพร้อมกันแต่ละ Transaction จะต้องทำงานแยกจากกันเพื่อป้องกันปัญหาข้อมูลเพี้ยน
D: Durability เมื่อ Transaction ทำงานสำเร็จและสั่ง Commit เรียบร้อยแล้ว ข้อมูลนั้นจะต้องถูกบันทึกลงในหน่วยเก็บข้อมูลแบบถาวร

### ความรับผิดชอบ
#### ฐานข้อมูล
A: จัดเตรียมระบบ Transaction Logs และคำสั่งพื้นฐานอย่าง BEGIN, COMMIT, และ ROLLBACK เพื่อใช้กู้คืนสถานะข้อมูลเดิมหากเกิดข้อผิดพลาดระหว่างทาง
C: ตรวจสอบโครงสร้างข้อมูล
I: จัดการการล็อคข้อมูลและควบคุม Concurrency เพื่อแยกการทำงานของแต่ละ Transaction
D: ทำการเขียนข้อมูลลง Transaction Log ลงพื้นที่เก็บข้อมูล

#### แอปพลิเคชัน
A: กำหนดขอบเขตของ Transaction บนโค้ด
C: ควบคุมความถูกต้องของ Business Logic
I: เลือกใช้ Isolation Level ให้เหมาะสมกับ
D: รอสัญญาณตอบกลับจาก Database ว่าสำเร็จเรียบร้อยก่อนที่จะส่ง Response HTTP 2xx กลับไปยืนยันกับผู้ใช้งาน
